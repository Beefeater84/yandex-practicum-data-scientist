BDD - Способ написания кода на основе пользовательских сценариев:

Зачем нужен: Чтобы разработчик и продукт менеджер говорили на одном языке.

Как достигается: Мы понятным языком описываем пользовательские сценарии. 
- **Given** (Дано) — начальный контекст/предусловия
- **When** (Когда) — действие, которое совершает пользователь или система
- **Then** (Тогда) — ожидаемый результат
Потом даем этот файл компилятору ( для каждого языка созданы компиляторы, понимающие что написано ) и компилятор пишет тесты. По сути тоже что TDD,  только описание тестов на нормальном языке.


Пример:
```gherkin
Feature: Авторизация пользователя

  Scenario: Успешный вход с корректными данными
    Given пользователь находится на странице входа
    When он вводит верный логин и пароль
    And нажимает кнопку "Войти"
    Then он должен быть перенаправлен на главную страницу
    And должно отображаться приветственное сообщение
    
```

Очень хорошо работает со спецификациями, где у нас есть общее описание фичей, а BDD обеспечивает тесты под них.

## Сложности:
- Не тестирует UI, только UC
- Изначально нужно создать словарь терминов. Когда мы говорим Авторизация - то агент не должен гадать что это за процесс. Он должен точно знать. Без словаря терминов - этот подход не работает.
